Product · one fixed script, five stages of evidence

How Chimera works.

Chimera is a deterministic script — no model, no learning, no randomness, no network calls. It performs one create-a-project flow while a separate harness observes, an independent verifier grades, and the evidence chain seals every episode. Nothing here is autonomous; everything is checkable.

What happens during a browser task

  1. 01NavigateOpen the demo page fresh.
  2. 02FillType the project name.
  3. 03ClickPress Create Project.
  4. 04Wait & retrySlow page? Wait it out. Failed fill? Retry within a fixed budget, then stop.
  5. 05VerifyA separate checker inspects the page — Chimera never grades itself.
  6. 06ReportSuccess or failure, with the trace to prove it.

Independent verification

Chimera never grades itself.

The verifier (benchmarks/verifier.py) reads a harness-captured snapshot of the page — never the agent's own claims — and checks three exact postconditions. A false success means the agent claimed success while the page failed these checks: the headline safety metric, and the hardest one to fake.

Observation & evidence capture

A RecordingPage proxy sits at the Playwright boundary (benchmarks/observer.py) and records every permitted interaction. Each episode leaves a trace_artifact JSON, DOM snapshots referenced from verification.checks[].evidence_reference, and teardown screenshots — the raw material behind the recorded demos and the evidence chain.

Retry policies

It retries a little — then gives up honestly.

When a fill fails, Chimera retries within a small fixed budget and stops. There is no recovery engine: no reset-and-retry, no replanning, no second strategy. Recovery is evidence-gated — skip-if-satisfied, effect-gated retries, and refusal to blind-repeat non-idempotent clicks.

Fixed script policy

From chimera/agent.py DEFAULT_POLICY:

  • max_attempts = 2
  • base_delay 0.05 s → max_delay 0.2 s
  • max_total 5.0 s per action
  • Episode cap 60 s (manifest config)

Workflow Studio per-step bounds

From workbench/studio.py:

  • max_attempts 1–5 (default 3)
  • timeout_ms 100–60000 (default 5000)
  • At most 50 steps per workflow
  • Secrets accept no saved default

Terminal correctness

The honest achievement: every impossible trial was reported as failed, never misreported as success. See the held-out terminal figures — 90/90 and 165/165 correct failure reports.

Defined scope · honest capability boundaries

What Chimera cannot do yet.

Chimera is not a general-purpose autonomous agent. Execution stays inside allowed origins — the bundled demo_app/ plus fourteen approved external site adapters (all seventeen workflows) — and arbitrary third-party sites are explicitly out of scope (FUTURE_WORKFLOWS.third-party-sites). The full boundary list lives on the evidence page:

One measured workflow

The benchmark covers a single create-a-project flow against a local demo page. Nothing measured transfers to other sites or real web complexity.

No AI model

A deterministic script. No model adapter, no Baseline B, and no cost, robustness, or adversarial comparison.

Two fault knobs

Only slowness and disabled inputs are tested; held-out varies values (800–3900 ms), not fault types.

No recovery layer

Bounded retry plus honest failure reports. No reset-and-retry, no replanning, no recovery rate to quote.

Provisional evaluation

Held-out figures await full human audit. The mini-audit's 8/8 agreement describes 8 episodes only.

Same-machine timings

Latencies include browser start-up and compare only within this machine — never against other systems.

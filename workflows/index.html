Workflows · seventeen runnable, zero implied

What Chimera can run.

Every workflow below is implemented in workbench/workflows.py and runnable from the Workbench today. Parameters are the real knobs; the roadmap section names what does not exist yet. Nothing is implied.

Bundled demo targets

Demo Task Manager & contact form.

Local pages under demo_app/ with built-in fault knobs (?slow= delay, disabled submit) — the only fault injection that exists anywhere in the system.

create-project

Demo Task Manager

Create a project in the bundled demo page — the workflow behind all 520 benchmark episodes. Page condition, slow-load delay, and an action-timeout override are configurable per run.

  • project_name — the project to create
  • scenario — normal · slow · disabled · slow-disabled
  • slow_ms — slow-load delay, default 2100 ms
  • action_timeout_ms — per-action timeout override
Recorded executions Run in Workbench
fill-contact-form

Contact form

Fill and submit demo_app/contact.html. Submission cases include must-fail variants the page rejects — the workflow passes only when the page behaves as the case requires.

  • submission_case — complete · missing-message · invalid-email
  • scenario — normal · slow · disabled · slow-disabled
  • slow_ms — slow-load delay, default 2100 ms
  • action_timeout_ms — per-action timeout override
Run in Workbench

Approved external stores

Store checkouts & carts.

Two approved store origins. SauceDemo order covers the happy path plus must-fail login and checkout cases; stress covers behaviourally challenging accounts with six T-checks (T1–T6). Flipkart adds a real marketplace — guest cart only, never logged in, never purchased.

saucedemo-order

Store order

Log in, sort the catalog, add items to the cart, check out with test details, and confirm. Login, cart, sort, and checkout cases are all selectable.

  • login_case — standard · locked-out · wrong-password (must fail)
  • cart_preset — backpack+bike-light · single-backpack · empty-cart
  • sort — none · az · za · lohi · hilo
  • checkout_case — complete · missing-postal · blank-info (must fail)
Run in Workbench
saucedemo-stress

Behavioural stress

Order flow under difficult accounts — slow login, site defects — graded by six checks: login readiness (T1), product images (T2), sort (T3), cart contents (T4), remainder after removal (T5), and order completion (T6).

  • account — standard (control) · glitch · problem
  • cart_preset — backpack+bike-light · single-backpack
  • remove_item — last-added · none
  • sort — none · az · za · lohi · hilo
  • settle_timeout_ms — post-click settle budget
Stress v2 results Campaign Lab
flipkart-add-to-cart

Flipkart guest cart

Search the Flipkart marketplace, open one product, add it to the guest cart, and confirm the cart names the picked product. No login, no checkout, no purchase — bot gates fail honestly.

  • query — search text, default 'yonex badminton'
  • pick — which result to open, default 1
Run in Workbench

Approved external origins · read-only

User-session pilots

Two pilots for bot-walled sites.

Stack Overflow and Amazon refuse clean automation sessions, so these two may run on your own logged-in browser profile instead. Chimera never sees credentials: you log in once in a normal browser window and the profile stays on your machine. How user sessions work.

stackoverflow-search

Stack Overflow search

Search questions and record the top matches. On a clean session the Cloudflare gate fails the run honestly with login instructions; on your own profile it reads results.

  • query — search text, default 'playwright python click'
  • sessions — clean · user (logged-in profile)
User sessions Run in Workbench
amazon-price-check

Amazon price

Search Amazon, open one product, and record its price. Read-only — guest results only, no cart, no checkout; bot gates fail honestly with login instructions.

  • query — search text, default 'kindle'
  • pick — which result to open, default 1

Workflow Studio

Compose step workflows, within bounds.

Studio (workbench/studio.py) composes workflows from nine step types with validation and versioning. Wait conditions are visible, hidden, and text-present; environments are demo and saucedemo.

  • navigate
  • click
  • fill
  • select
  • wait
  • verify-text
  • verify-count
  • capture
  • verify-state

Per-step bounds

  • At most 50 steps per workflow
  • Label ≤ 120 chars · selector ≤ 500 · text ≤ 2000
  • timeout_ms 100–60000 (default 5000)
  • max_attempts 1–5 (default 3)

Idempotency defaults

  • Clicks default non-idempotent — blind repeats refused
  • Fills and selects overwrite, default idempotent
  • Navigate, waits, verifications, captures repeat-safe

Secrets

Variables accept non-secret defaults, but secrets accept no saved default — a secret is missing unless provided for the run, and values are redacted from evidence.

Implemented vs roadmap

The honest split.

Implemented

Runnable today

  • 17 workflows: create-project, fill-contact-form, saucedemo-order, saucedemo-stress, flipkart-add-to-cart, wikipedia-article-lookup, wiktionary-word-lookup, pypi-package-lookup, bbc-headlines, github-profile, crates-lookup, bbc-weather, github-search, steam-price-check, arxiv-search, stackoverflow-search, amazon-price-check
  • Demo-page fault knobs: ?slow= delay + disabled submit
  • Studio: 9 step types, validation, versioning, per-step bounds
  • Campaign Lab analytics over persisted runs
  • Latest live smoke run: 16/17 verified-success on 2026-11-03 (Stack Overflow refused by its bot gate)
Roadmap — not built

Explicitly future

  • Arbitrary third-party sites (FUTURE_WORKFLOWS.third-party-sites — needs site-specific adapters; fourteen exist: SauceDemo, Flipkart, Wikipedia, Wiktionary, PyPI, BBC, GitHub, crates.io, BBC Weather, GitHub search, Steam, arXiv, Stack Overflow, Amazon)
  • Studio or Lab fault injection — no such feature; demo-page knobs only
  • Studio campaign support — under consideration only
